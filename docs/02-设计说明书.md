## 2. 开发概要

### 2.1 开发的目的和背景

#### 目的
构建面向高校学生的校园二手拍卖与即时通讯一体化平台。以实时拍卖模式实现价格发现，以内置IM替代第三方通信工具，以校园身份认证构建可信交易环境。

#### 背景
高校二手交易需求旺盛但现有渠道（QQ群/微信群/闲鱼）存在信息混乱、价格不透明、隐私泄露、交易无保障等问题。本项目在软件工程实验课程框架下实施，完整实践需求→设计→编码→测试全流程。

## 4. 实现方式

### 4.1 用户与认证功能 (M1)

#### 4.1.1 功能概要
提供用户注册、登录、JWT无状态认证、个人信息管理功能。支持学号+邮箱注册，BCrypt密码加密。实现RBAC角色权限控制。

**核心流程：**
```
注册流程：学号 + 邮箱 + 密码 → BCrypt加密存储 → 返回成功
登录流程：学号 + 密码 → 验证 → 生成JWT(AccessToken 30min + RefreshToken 7d) → 返回Token
鉴权流程：请求携带Token → JWT过滤器校验 → @PreAuthorize权限检查 → 放行/拒绝
```

#### 4.1.2 功能详细

| 功能点 | 说明 | 输入 | 输出 |
|--------|------|------|------|
| 注册 | 学号+邮箱+密码+手机号注册 | RegisterDTO | 成功/失败消息 |
| 登录 | 学号+密码登录 | LoginDTO | JWT Token |
| Token刷新 | RefreshToken换取新AccessToken | RefreshToken | 新AccessToken |
| 获取个人信息 | 查看当前用户资料 | — | UserVO |
| 编辑个人信息 | 修改昵称/头像/手机号/简介 | UpdateUserDTO | UserVO |
| 查看用户主页 | 查看任意用户公开信息 | userId | UserProfileVO |
| 身份审核(管理) | 管理员审核用户身份认证 | userId + 审核结果 | 成功消息 |

### 4.3 实时拍卖引擎功能 (M3)

#### 4.3.1 功能概要
实现英式升价拍卖。买家实时出价，通过WebSocket(STOMP)推送出价更新给所有围观用户。拍卖倒计时结束后自动判定得主。使用Redis缓存当前最高出价，MySQL持久化出价记录。

**核心流程：**
```
卖家发布拍卖商品 → 设置起拍价+时长 → 拍卖开始
买家浏览 → 出价(须高于当前最高价) → Redis原子校验+缓存 → STOMP广播
  → MySQL异步持久化出价记录
拍卖到期 → 定时任务判定得主 → 广播成交结果 → 生成订单
```

#### 4.3.2 功能详细

| 功能点 | 说明 | 实现要点 |
|--------|------|---------|
| 开始拍卖 | 商品发布时自动启动拍卖 | 记录auction_start, auction_end |
| 出价 | 用户提交出价 | Redis Lua脚本原子校验(出价 > 当前价) → 更新缓存 → STOMP广播 |
| 实时推送 | 出价更新推送给所有订阅者 | `/ws/auction/{productId}` STOMP订阅 |
| 倒计时 | 前端独立倒计时 + 后端定时任务兜底 | 后端`@Scheduled`每分钟检查到期拍卖 |
| 成交判定 | 拍卖到期确定得主 | 最高出价者 = winner，更新product表 |
| 出价历史 | 查看完整出价记录 | bids表分页查询 |

#### 4.3.3 相关功能
- 关联M2：从商品模块获取拍卖商品信息
- 关联M1：出价人身份验证
- 关联M5：成交后自动生成订单
- 关联M4：成交后通知买卖双方

#### 4.3.4 用户接口

| 接口 | 方法 | 说明 |
|------|:--:|------|
| `/api/v1/products/{id}/bids` | GET | 出价记录列表 |
| `/api/v1/products/{id}/bids` | POST | 提交出价 |
| `/ws/auction/{productId}` | WS(订阅) | 实时出价推送 |

**图4-3 拍卖出价时序图（文字描述）**：
```
Bidder → POST /bids → AuctionService.placeBid()
  → Redis Lua Script (验证出价 > currentPrice) → 更新Redis
  → SimpMessagingTemplate.convertAndSend() → STOMP广播所有订阅者
  → @Async bidRepository.save() → MySQL持久化
  → WebSocket推送 "{type:NEW_BID, bidAmount:xx, bidder:xx}" → 所有围观用户
```

**出价并发处理**：
- 使用Redis Lua脚本保证原子性：校验出价有效性 + 更新当前最高价在一个原子操作中完成
- MySQL bids表使用`product_id + bid_amount`唯一索引防止重复出价
- 用户前端按钮在提交后锁定1秒，防重复点击

## 7. 注意限制事项

### 7.1 制约/限制事项

| 限制项 | 说明 |
|--------|------|
| 支付功能 | 使用模拟支付，不接入真实支付网关 |
| 短信/邮件 | 使用站内通知代替 |
| 图片存储 | 开发/演示阶段使用本地存储 |
| 移动端 | 仅Web响应式适配，无原生App |
| AI推荐 | 使用简单热门推荐，不实现复杂推荐算法 |
| 实名认证 | 学号+人工审核，不接入学校SSO |

### 7.2 假定事项

1. 用户通过学号/工号注册即视为校园身份认证通过（管理员审核通过）
2. 服务器运行在校园内网或公网云主机，网络环境稳定
3. 并发用户量在200以内（课程演示规模）
4. 用户浏览器支持WebSocket和现代JS特性

### 7.3 特记事项

1. 拍卖倒计时以**服务器时间**为准，前端倒计时仅用于展示
2. 拍卖成交后自动生成订单，买卖双方不可取消（保证拍卖严肃性）
3. IM消息仅保留文字和图片链接，不支持视频/文件传输
4. 敏感词过滤使用本地词库，不接入第三方内容审核API

## 8. 附录

### 8.1 业务规则

| 编号 | 规则描述 |
|:--:|---------|
| BR-01 | 出价金额必须大于当前最高出价，最小加价幅度为1元 |
| BR-02 | 拍卖到期后，最高出价者自动成为得主；若无出价，拍卖流拍 |
| BR-03 | 一口价商品被购买后立即下架 |
| BR-04 | 订单仅在"待付款"状态可取消 |
| BR-05 | 交易完成后双方须在7天内评价，超时默认好评 |
| BR-06 | 用户信誉分 = 好评数×1 - 差评数×2，初始100分 |
| BR-07 | 同一用户对同一商品短时间内(3s内)多次出价，仅记录最高一次 |
| BR-08 | 每个用户同时最多进行10个IM会话 |

### 8.2 术语表

| 术语 | 定义 |
|------|------|
| 英式拍卖 | 出价从低到高的升价拍卖，价高者得 |

| 流拍 | 拍卖结束时无人出价 |
